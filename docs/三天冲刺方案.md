## 附录 A：路径规划前置依赖表（开发者 A 直接落地）

### A1. 数据已就绪（不用新造）

- Schema：`backend/src/schemas.py:464-477`
  - `LearningPathNode`: `node_id / title / resource_id / resource_type / difficulty / estimated_duration_minutes / depends_on / is_completed`
  - `LearningPath`: `learner_id / nodes / total_estimated_hours / created_at`
- 输出槽：`ReportResponse.learning_path: Optional[LearningPath]`（`schemas.py:501`）
- 前端：`LearningPathMap`（`vaultshield-hero.tsx:499`）已能渲染，**零前端改动**
- 输入：`diagnosis_result.skill_gaps`（含 `priority / topic / current_level / target_level`）+ `knowledge_map`

### A2. 前置依赖表（手写 DAG，按现有 6 个前置测试知识点）

| node_id | 知识点（topic） | 前置依赖 | 建议资源类型 | 预设难度 | 预设时长(分) |
|---|---|---|---|---|---|
| kp_safety | 安全急停链路 | —（根节点，最先学） | guide + pitfall_guide | beginner | 30 |
| kp_coord | 机器人坐标系（基/工具/用户/大地） | — | lecture | beginner | 30 |
| kp_motion | 运动指令（PTP/LIN/CIRC） | kp_coord | lecture + guide | beginner | 40 |
| kp_sim | 离线仿真（RobotStudio / ROBOGUIDE） | kp_coord | guide | beginner | 45 |
| kp_teach | 示教器编程（FANUC/ABB/KUKA） | kp_coord, kp_motion | guide + project | intermediate | 60 |
| kp_ros | ROS2/Gazebo 仿真 | kp_motion, kp_sim | guide + project | advanced | 60 |
| kp_fault | 故障诊断（SRVO-068 等） | kp_coord, kp_motion, kp_teach | guide + pitfall_guide | intermediate | 50 |

> 表可随知识库实际文档增删节点；**关键词映射**：`skill_gaps[].topic` 含"坐标"→kp_coord、"运动/指令"→kp_motion、"仿真"→kp_sim（含 ROS/Gazebo 再细分）、"示教"→kp_teach、"故障/SRVO"→kp_fault、"安全/急停"→kp_safety。

### A3. 生成算法（纯规则，不调 LLM）

```
输入: diagnosis_result.skill_gaps / knowledge_map / recommended_difficulty
输出: LearningPath

1. 把 skill_gaps 的每个 topic 按关键词映射到 A2 表的 node_id
2. 只保留"薄弱"节点：current_level < target_level（或 priority ∈ {critical, high}）
3. 对保留节点按 depends_on 做拓扑排序（前置先排）
4. depends_on 只保留"也在本次路径内"的前置节点，砍掉路径外的引用
5. difficulty：优先取诊断的 recommended_difficulty；节点预设难度与画像差 2 档时用画像值覆盖
6. estimated_duration_minutes 取 A2 预设值；total_estimated_hours = 各节点时长之和 / 60
7. 写回 ReportResponse.learning_path（is_completed 默认 False）
```

### A4. 落地位置

- 新增 `backend/src/agents/k1_path_planner.py`，暴露 `build_learning_path(diagnosis) -> LearningPath`；
- 在 `main.py` 的 `_generation_response`（`main.py:464`）里加 `"learning_path"` 字段调用它（同步 `/api/generate` 与异步 `/api/generate/start` 共用该函数，一处改两路覆盖）；
- 单测：`backend/tests/test_k1_path_planner.py`，断言"拓扑序正确 + depends_on 不悬空 + 节点数 > 0"。

## 附录 B：脚手架三档提示模板（开发者 B 直接落地）

### B1. 三档框架

| 档位 | 做什么 | 给不给答案 |
|---|---|---|
| **L1 引导思考** | 反问 / 缩小问题范围，让学生自己先判断 | 否 |
| **L2 给线索** | 指到手册章节 / 关键词 / 排查方向 | 否（给方向） |
| **L3 给答案** | 完整答案 + 解析 + 来源（复用 `k1_exercise` 的标准答案） | 是 |

### B2. 触发规则（纯规则判断）

- **触发脚手架**：学生输入是疑问句（含"为什么 / 怎么做 / 是什么 / 如何 / 怎么"），且能定位到 `knowledge_map` / `skill_gaps` 里的某个知识点。
- **直接回答（不硬套）**：非疑问句、闲聊、或定位不到知识点 → 走原答疑，不强行脚手架。
- **升级节奏**：学生回答 L1 的引导后，再给 L2；卡住或明确说"不知道"→ 给 L3。

### B3. 模板（以 SRVO-068 为例，可直接复制改）

**L1（引导思考）：**
> 先别急着看答案。想一下：`SRVO-068` 是 FANUC 的哪一类故障——是**通信/数据传输**类，还是**伺服/驱动**类？把你的判断打给我，我帮你验证。

**L2（给线索，学生判断对或卡住后给）：**
> 方向对了一半。按知识库排查顺序：先做急停与上锁挂牌、断电放电，再去查伺服放大器侧 `CRF8/RP1` 接头和电机侧 `Pulsecoder` 接头是否松动/氧化/进液，之后才是电缆与屏蔽接地。告诉我你检查后卡在哪一步，我接着带你。

**L3（给答案 + 解析 + 来源）：**
> SRVO-068 是 FANUC 的 **DTERR 报警**——控制器请求串行脉冲编码器数据，但编码器未返回串行数据。处理顺序为：① 记录组号 `G:i`、轴号 `A:j`、伴随报警与报警历史 → ② 急停并执行上锁挂牌/断电，等控制柜与伺服单元放电 → ③ 检查伺服放大器侧 `CRF8/RP1` 与电机侧 `Pulsecoder` 接头（松动/污染/进液）→ ④ 检查机器人连接电缆、机械单元内部电缆与屏蔽接地 → ⑤ 仍无异常时按「Pulsecoder → 伺服放大器 → 机器人连接电缆 → 内部编码器/电机电缆」顺序替换验证 → ⑥ 重新上电，低速手动验证反馈后再恢复生产。依据：`K3_20260805_001_fanuc_srvo068_error_fix`（知识库原文）。建议配套练习：复习编码器/串行通信链路排查与报警复位边界。
